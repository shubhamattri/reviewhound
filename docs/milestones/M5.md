# M5: depth and accuracy

## What was built

1. **JavaScript and Go in the index** (`index/treesitter.py`, `paths.py`).
   - JavaScript: `.js .jsx .mjs .cjs`. Go: `.go`.
   - Both index definitions, the calls inside each one, callers and the enclosing definition, like Python and TypeScript.
   - Go methods are qualified by receiver (`func (s *Store) Save` gives `Store.Save`, including pointer and generic receivers).
   - Go `type` specs (struct, interface, alias) are indexed as `type`. Calls through a `selector_expression` record the field name.
   - `javascript` and `go` are allowed in `languages` and on by default. They route to the standard tier like other code.
   - `CodeIndex(languages)` only parses the configured languages. `covers(path)` says whether facts about a path can be checked.
2. **Checker fixes** (`checker.py`).
   - a. Dotted names. `Foo.save` must match a definition qualified `Foo.save`, or one ending `.Foo.save`.
     - If `Foo` is defined but has no such member, the claim is false.
     - If `Foo` is not defined in indexed code (for example `requests.get`), the claim is unknown.
     - If the member is named inside `Foo`'s body but is not a definition (a field or attribute), the claim is unknown, because fields are not indexed.
     - Undotted names behave as before.
   - b. Quotes spanning blank lines. Blank lines are skipped on both sides when matching, and `find_quote_spans` returns each match's real first and last file line. `_locate` uses that span instead of the quote's line count.
   - c. Languages the index does not cover give `unknown`, not `false`. This applies to a quote claim on an unread file, to a symbol that is not found, and to a caller that is not defined, whenever the claim's file (or the finding's file) is in an uncovered language. The pipeline passes `cfg.languages` to the index, so a language turned off in config also counts as uncovered.
   - d. `Finding.identity`. This is an optional stable id that `fingerprint` uses when it is set. The secret scanner sets it to `sha256("reviewhound-secret\0" + value)[:16]`. The raw value is never stored.
3. **Comments on deleted lines.**
   - `Hunk.deleted` and `FileDiff.deleted_lines` hold base-side line numbers.
   - When an evidence quote cannot be placed on changed head lines, either because it is missing from head or because it only sits in unchanged code (a removed guard often still exists in other handlers), the checker reads the base version through a lazy `base_reader`. The pipeline passes `vcs.read_file(repo, base_sha, path)`, and renamed files are read by their old path.
   - A deleted line only counts when the base text at that line equals the text the patch shows being deleted. If the base version does not line up with the diff (for example the base branch moved past the merge base), the finding is dropped with the reason "base version of X does not match the diff".
   - A quote that touches a deleted line is kept with `side="LEFT"` and that base line number. A quote found in the base only on unchanged lines is dropped. A quote found nowhere is dropped with the reason "evidence quote does not exist at head or on deleted lines".
   - Files deleted by the PR are now reviewable this way. A finding on a deleted file with no quote is dropped.
   - A failed base read drops only that finding, with the reason "base version of X could not be read (ErrorType)". It is logged and read once per path.
   - `ReviewComment.side` (default `RIGHT`) is sent to GitHub and shown in the dry-run payload.
   - Policy de-duplicates per `(file, side, line)`.
4. **Skipped files are listed.**
   - `Diff.skipped` records files whose patch GitHub omitted. With changes > 0 the reason is "diff too large for GitHub to return". An added or modified file with 0 changes gets "no text diff (binary, empty or mode change)". A rename with no content change is not listed.
   - `Snapshot.skip_reason` reports files the snapshot refused: over the size cap, or not UTF-8.
   - `pipeline.not_reviewed` merges both lists, leaves out ignored paths, and the review body lists each as `- not reviewed: <path> (<reason>)`.
5. **Eval set: 12 to 32 cases.**
   - 6 JavaScript and 7 Go seeded-bug cases.
   - 6 clean cases, including dotted-symbol traps in Python, TypeScript and JavaScript.
   - 2 deleted-line bugs (Python, Go), two secrets on identically shaped lines, a quote spanning a blank line, and a Ruby finding.
   - Every recorded answer carries plausible hallucinations.
   - `score` matches `side`. `build_cases.main(root)` can write anywhere, and a test checks that the committed cases equal the generator's output.

## Not done, and why

- The model still cannot see base line numbers for deleted lines. `context.render_hunks` shows them without numbers. LEFT findings are located by their quote, so this works, but a model citing a line has nothing to cite. `context.py` is outside this milestone's files.
- `side` is not stored in the SQLite `findings` table. Re-review matching is by fingerprint, which does not involve side, so nothing breaks. A later report that wants to show the side needs a column.
- Go interface method signatures (`method_elem`) and JavaScript class fields are not indexed as definitions. Dotted claims about them return unknown (named inside the owner), not true.
- `covers()` is by language only. A file in a covered language that the index skipped (ignored path, past the 5,000-file cap) still gets "not found at head" (false) for a quote claim, as before M5.

## Risks for whoever merges this

- **A LEFT finding is accepted on its quote alone.** A finding that quotes old, buggy code which the PR deleted to fix it (for example `eval(x)` replaced by `literal_eval(x)`) now survives as a LEFT comment instead of being dropped. The checker cannot tell whether the deletion is what the finding is about. Claims still run against head. A follow-up could require at least one true claim for LEFT findings.
- **Inherited members.** Dotted claims about inherited, mixin or Go-embedded members return false when the member is not named in the owner's body. Under the default `drop_unverified`, both false and unknown keep the finding off the PR, so the impact is small.

- **Secret fingerprints change.** A secret already posted on an earlier head now has a new fingerprint (identity based instead of quote based). It will be posted once more after upgrade. Model findings are unaffected.
- **Base reads cost API calls.** On GitHub, a finding whose quote is not at head now costs one contents API call per distinct file. These are cached per review and made only for such findings. A failed read drops only that finding.
- **`Snapshot` protocol gained `skip_reason`.** Any out-of-tree snapshot class must add it. In-tree, `DictSnapshot` and `DirSnapshot` have it.
- **Parallel edits.** Merge conflicts are likely in `pipeline.review()` around the index and verify stages, and in `poster.build_review`. Keep both sides.
- The two new eval cases with `side: LEFT` need the side-aware `score`. Do not merge the cases without `evals.py`.
