# M6: Operations

## What was built

1. **Postgres backend** (`src/reviewhound/backends/postgres.py`): `PostgresQueue`,
   `PostgresStore`, `PostgresMetrics`, with psycopg 3 as an optional extra
   (`pip install reviewhound[postgres]`, also in the dev group so mypy and tests see it).
   - Claims use `SELECT ... FOR UPDATE SKIP LOCKED`; expired final-attempt leases are marked dead
     with the same skip-locked subquery.
   - Every read-then-write is one transaction (one connection per operation, committed on
     success, rolled back on any exception).
   - Enqueue takes a per-PR advisory lock, so superseding and the duplicate-key path behave
     exactly like SQLite's `BEGIN IMMEDIATE`.
   - The store upsert keeps the same protected states (declined, resolved, posted, reopened).
   - DDL is a list of statements per area (`QUEUE_DDL`, `STORE_DDL`, `METRICS_DDL`) run under an
     advisory lock, so a later column or table (installation_id, comment_links) is one more entry.
   - Times are epoch seconds from the injected clock, as in SQLite, so the fake clock tests apply.
2. **Backend selection** (`src/reviewhound/backends/__init__.py`): `REVIEWHOUND_DATABASE_URL`
   (or `--database-url`) of `postgresql://` / `postgres://` selects Postgres; empty selects
   SQLite in `--home`; any other scheme is refused without echoing the URL.
3. **Lease heartbeat** (`src/reviewhound/heartbeat.py`): while a job runs, a daemon thread calls
   `extend_lease(job)` every `lease_s / 3` using the lease token. `LeaseLost` stops it and logs a
   `lease_lost` error event; any other error is logged and retried on the next beat. The thread
   is joined before `complete`/`fail`. `extend_lease` was added to both queues.
4. **Checkout race** (`GitHubVCS._checkout`): fetch into a private `mkdtemp` beside the
   destination, write the completion marker, then rename into place under a per-sha `flock`.
   A destination that already has the marker is success (the temp copy is discarded); a
   destination without one can only be a half-done checkout from before M6 and is replaced.
   Failed fetches remove their temp dir. Nothing ever deletes a live or in-progress checkout.
5. **Metrics** (`src/reviewhound/metrics.py`): the worker records per job, after the job state
   is written, `reviews_total{outcome}`, `review_stage_seconds_sum/_count{stage}`,
   `review_cost_usd_total`, and on exceptions `jobs_failed_total{error}`. Counters are durable
   rows (`metric_counters`, in `queue.db` or Postgres), so `serve` reports what every worker
   recorded. A metrics write failure is logged and never fails or retries the job.
   - `GET /metrics` on the webhook server (Prometheus text 0.0.4) adds `queue_backlog{state}`,
     `oldest_queued_age_seconds`, `queue_stuck_jobs` and `backlog_alarm`; a render error is a 500.
   - `reviewhound stats` prints the same snapshot; `stats --prometheus` prints the exact text.
   - `BacklogAlarm`: `stuck_count(older_than_s)` (default 600, `--backlog-alarm-s`) > 0 logs a
     structured `backlog_alarm` error at most once per interval (`--backlog-alarm-interval-s`,
     default 300) and sets the `stuck` / `active` gauge. `run_forever` checks it each loop; an
     alarm error is logged and never stops the worker.
6. **Packaging**: `Dockerfile` (python:3.12-slim, uv 0.10.9, git, non-root uid 10001, no secrets,
   `HEALTHCHECK` on `/healthz`, optional `INSTALL_CLAUDE_CLI=1` for worker images),
   `.dockerignore`, `docker-compose.yml` (`serve` + `worker` + `postgres` profile, every secret
   from env with `:?` guards), and `docs/deploy.md`.

## Not done, and why

- **Docker image build and run are unverified.** The Docker daemon is not running on this
  machine. I read the Dockerfile line by line, ran `docker compose config` (valid, and it
  refuses to start with a secret missing), and ran the Dockerfile's two `uv sync --frozen
  --no-dev --extra postgres` steps in a scratch copy on the host (psycopg imports, `stats`
  runs, pytest absent). The `apt-get`, the Node/`claude` install, the non-root user and the
  healthcheck have not executed.
- **`CLAUDE_CODE_OAUTH_TOKEN` in containers** is how I expect the `claude` CLI to authenticate
  headless; not tested here (no live model calls are allowed in this build).
- **No `requeue` CLI command**; the method exists on both queues.
- **No migrations framework.** Schema is `CREATE ... IF NOT EXISTS`; an added column needs an
  `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` entry in the DDL list.
- **Cost of a failed attempt is not counted**: the reviewer raises before returning its cost.
- **A review that loses its lease keeps running to the end**; it is not interrupted. Its result
  is refused by `complete` and `claim_post` still allows only one post per head.
- **Stale temp checkout dirs** from a worker killed mid-fetch (`.<sha>.xxxx`) are not swept.

## Risks for whoever merges this

- **Installation_id / comment_links work**: add the new column to both `_SCHEMA` in
  `queue.py` and `QUEUE_DDL` in `backends/postgres.py` (and `PostgresQueue.enqueue` if the
  signature changes); same for `comment_links` in `STORE_DDL`. The shared test fixture will
  then run their new tests on Postgres too, and fail loudly if the Postgres side is missed.
- `tests/conftest.py` drops `jobs, reviews, findings, posts, feedback, metric_counters` in the
  test database before each Postgres test; new tables must be added to `_PG_TABLES`.
- `worker.run_one` / `run_forever` now take `WorkerQueue`; anyone adding a queue method the
  worker uses must add it to that protocol and to `PostgresQueue`.
- The existing `Store.__init__` has the same missing-WAL pattern I fixed in `SQLiteMetrics`;
  a brand-new `reviewhound.db` hit by several writers at once could see `database is locked`.
  Not changed here (shared file, outside this milestone).
- `/metrics` is unauthenticated on the webhook port; `docs/deploy.md` says to restrict it.
- The checkout lock uses `fcntl.flock`: POSIX only, and only effective between workers that
  share a local filesystem (the normal setup).
